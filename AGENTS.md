# AGENTS.md — `HiveMind-assets`

Guidance for AI coding agents (and humans) working in this repository. Read it
fully before making changes. It encodes conventions that are not obvious from
the files and that, if ignored, produce work that will be rejected.

## Repo

This repo holds the shared logos, diagrams, and node-icon assets for the
[HiveMind](https://github.com/JarbasHiveMind) ecosystem — a protocol for
connecting satellite devices to a hub running
[OpenVoiceOS](https://github.com/OpenVoiceOS). It is pure asset storage: no
source code, no build, no tests. `logo/` holds the HiveMind logo (rendered
PNGs plus raw SVGs under `logo/raw/`); `nodes/` holds per-client-type icons,
several kept as editable GIMP `.xcf` sources alongside their exported `.png`.
`readme.md` documents licensing and logo usage; `LICENSE` is CC0 1.0
Universal. The hub is
[HiveMind-core](https://github.com/JarbasHiveMind/HiveMind-core); the wire
protocol and specs live in the
[architecture](https://github.com/JarbasHiveMind/HiveMind-architecture) docs.

## Layout / build / test

- No package, no build, no test suite — this repo is binary/vector assets
  only. There is nothing to `pip install` or `pytest`.
- Keep exported and source formats paired and organized: a `.png` shipped for
  use should have its editable source (`.svg` under `logo/raw/`, or `.xcf`
  next to the export under `nodes/`) committed alongside it, not only the
  flattened export.
- Do not commit large or redundant binaries carelessly — check image
  dimensions and file size are reasonable for the asset's actual use (icon
  vs. banner) before adding it, and do not add near-duplicate exports of the
  same source.

## Working agreement (org-wide law)

- **Git identity is always** `JarbasAi <jarbasai@mailfence.com>`. Never set a
  per-repo override.
- **Never push `dev` or `master`.** Work on a feature branch and open a
  **draft** PR into `dev` (this repo's default branch is `master` — target
  it directly since there is no separate `dev`). A human merges. You do not
  merge your own PRs.
- **Never merge or modify `Release X → master` PRs.** They are the
  maintainer's stable-release mechanism, generated by automation.
- **One commit per PR** (squash before pushing). Conventional commits;
  `feat:` only for a user-visible new capability. `fix:`, `docs:`, `chore:`,
  `ci:` otherwise.
- **Disclose AI authorship.** Every PR/issue/comment an agent writes carries,
  at the top: `> 🤖 Auto-generated by <model> via Claude Code — NOT
  human-reviewed. Verify before acting.` PR bodies are plain human prose
  (3–6 short paragraphs), no tables or section-symbol spray.
- **Never edit someone else's** issue, PR description, or comment. Add a
  comment instead; on your own PRs, edit the body rather than piling on
  comments.
- Keep durable text (README, docs, PR bodies, comments) timeless and
  standalone: no dates, no "currently/now/new", no meta-commentary about the
  edit itself.
- No scratch files, committed virtualenvs, `__pycache__`, `.pyc`, or
  unrelated build artifacts in a PR. `git show --stat` shows only intended
  files.
- **Keeping this AGENTS.md current is a quality gate.** Any PR that changes
  this repo's asset organization or licensing terms updates AGENTS.md in the
  same PR.

- The HiveMind logo was created by [AIIX](https://github.com/AIIX/); credit

  non-CC0-licensed source, say so plainly in the PR — do not relicense
  someone else's work as CC0 by omission.

## Repo-specific rules

- This is a tooling/infra asset store, not application code: there is no
  test harness to satisfy, adversarial-test and dependency-floor-pin rules
  from the org-wide template do not apply here.
- Prefer adding/editing the raw source (`.svg`/`.xcf`) and re-exporting the
  flattened format over hand-editing a `.png` directly, so the asset stays
  maintainable.
- Naming should stay consistent with the existing convention (lowercase,
  underscore- or hyphen-separated, client/node name matching the app it
  represents) so downstream repos referencing these assets by path don't
  break.
